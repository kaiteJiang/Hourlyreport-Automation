# v117 快商通动态写库与人工路径修复设计

## 背景与根因

v116 将旧版 Java/JCEF 数据库的严格一致性保护应用到了既有 Electron 链路。Electron 客户端运行期间会持续更新 `VISITOR*.db` 及其旁路文件；注册表在推广 ID 和必需接口读取前后比较完整文件指纹，只要文件大小或时间戳变化，就把本来成功的读取误判为 `database_busy_or_timeout`。

人工路径能力已经存在于顶部“系统 → 快商通模式”二级菜单，但用户更常使用的内嵌设置区域只显示“API 自动获取/人工导出对话”。自动发现明确报程序目录或数据目录无效时，也没有提供一次性选择引导。

## 修复目标

1. Electron 客户端持续写入现有数据库时，本地 API 仍能刷新身份并进入就绪状态。
2. Electron 身份、安装根或数据库路径集合变化时仍然失效关闭，不能复用旧绑定。
3. 旧版 Java/JCEF 数据库继续使用完整文件指纹，读取期间变化仍拒绝绑定。
4. 内嵌快商通设置区域直接提供程序目录、数据目录和重新扫描入口。
5. 仅在明确的程序目录或数据目录错误时，每次 GUI 生命周期最多自动打开一次相应目录选择框；取消后不循环弹出。

## 一致性策略

`KstIdentityRegistry` 使用按客户端家族区分的指纹比较：

- Electron：比较客户端家族、安装根、身份和数据库路径集合；忽略同一路径文件的大小、修改时间和 WAL/SHM/journal 状态变化。
- Java/JCEF：比较完整指纹，包括数据库及旁路文件的大小与修改时间。

Electron 运行态缓存继续使用已有 `_runtime_input_state`，数据库内容变化仍会导致运行态状态变化；本修复只取消把正常动态写入误判为身份失效。

## GUI 交互

内嵌“快商通模式”展开区增加：

- 选择快商通程序目录
- 选择快商通数据目录
- 重新扫描快商通

三项复用现有 `MainWindow` 处理函数和 `runtime/kst_machine_settings.json` 原子保存逻辑，不新增配置格式。

当本地 API 状态首次返回“快商通客户端目录无效”或“快商通数据目录无效”时，GUI 在主线程调用对应目录选择框。`数据库忙或读取超时`、身份映射、客户端未运行等错误不触发路径窗口。

## 验证

- RED/GREEN：Electron 文件状态在读取中变化仍成功绑定。
- 回归：Electron 新增数据库路径仍使绑定失效。
- 回归：Java/JCEF 完整指纹变化仍被拒绝。
- GUI：内嵌入口存在、信号连接正确、导出模式禁用重新扫描。
- GUI：路径错误只弹一次；数据库错误不弹。

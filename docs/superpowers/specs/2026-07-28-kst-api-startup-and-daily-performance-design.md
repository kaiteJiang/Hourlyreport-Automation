# 商务通 API 启动与日报性能优化设计

## 背景与现场证据

2026-07-28 实机日志显示：

- GUI 于 09:04:40 完成基础环境检查，本地 API 于 09:05:58 就绪，等待约 78 秒。
- 当天 `tag_dictionary`、`visitor_card` 分别在 09:00:21、09:01:07 已写入日志，但 `visitor_info` 直到 09:05:55 才首次出现。
- 当前身份发现、推广 ID 读取、日志解析和注册表刷新分别只需约 0.09、1.06、1.06、1.21 秒，不是固定慢点。
- 昆明牛日报包含 13 条自动来源会话，现有实现逐条串行读取访客信息与名片，共发起 26 次只读请求，实测 13.70～14.36 秒，运行日志现场曾达到 28 秒。
- 相同 13 条会话的 4 路受控并发原型耗时 1.74 秒。

## 目标

在不改变自动来源白名单、项目身份映射、统计口径和失败策略的前提下：

1. GUI 启动后尽快建立可用的商务通本地 API。
2. 将常见日报的商务通读取时间从 14～28 秒降低到约 2～5 秒。
3. 避免长时间无反馈造成的“程序卡死”感。
4. 不持久化、不输出、不复用跨日认证参数或 Token。

## 非目标

- 不改百度 API、浏览器降级或 Excel 写入流程。
- 不把数据库中的所有历史记录视为自动来源。
- 不改小时报和日报的字段口径。
- 不使用数据库字段替代服务端权威会话字段。
- 不增加公网服务、远程代理或新的凭据文件。

## 方案一：接口地址安全回退

### 数据分类

日志中的数据分为两类：

- **非凭据数据**：接口 URL。允许从同一身份的历史本地日志中恢复。
- **认证数据**：公共查询参数、请求头和 Token。必须来自当天日志，只保存在内存。

历史接口 URL 不能使缺少当天认证材料的身份变为可用。

### 解析规则

1. 日志解析器扫描同一身份的本地轮换日志。
2. 接口 URL 可从历史日期提取，按日志时间保留最近一次值。
3. 当天出现相同接口的新 URL 时，自动覆盖历史值。
4. 公共查询参数和请求头继续只接受 `auth_date` 当天的日志行。
5. 身份注册表判定基础能力可用时，必须同时满足：
   - `visitor_info`、`visitor_card`、`tag_dictionary` 三个接口 URL 完整；
   - 当天公共查询参数存在；
   - 当天请求头存在；
   - 推广 ID 与项目保持严格一对一绑定。
6. 任一条件不满足时保持未就绪，不允许使用历史认证材料。

### 重试策略

- 未就绪状态的后台重试间隔由 15 秒缩短为 5 秒。
- 已就绪后继续复用现有轻量健康检查和 5 分钟完整刷新策略。
- 所有刷新继续在后台线程执行，不阻塞 Qt 主线程。

## 方案二：会话详情受控并发

### 并发模型

1. 仍先从自动推送或启动自动同步日志建立 `recId` 白名单。
2. 仍从只读 SQLCipher 数据库取得候选行，并只保留白名单内记录。
3. 每条会话内部保持顺序：
   - 先读取 `visitor_info`；
   - 取得 `visitorId` 后读取 `visitor_card`。
4. 不同会话之间使用最多 4 个工作线程并发。
5. 最终结果按开始时间和 `recId` 排序，保证输出稳定。

### 错误与完整性

- 任一工作线程失败时，本次 `collect` 整体失败。
- 不返回已完成线程形成的部分数据。
- 上层继续执行现有项目级失败策略：商务通指标按 0，百度数据继续。
- 不把失败结果写入会话缓存。
- 同一运行时的多个请求继续使用现有 single-flight 锁，避免重复构建同一批数据。
- 项目推广 ID 白名单检查、账户完整性检查和指标校验保持不变。

## GUI 体验

- 日报继续通过 `QProcess` 在子进程执行，不把网络或数据库工作移入 Qt 主线程。
- 保留现有 `[2/4] 读取商务通本地 API 日报` 阶段提示。
- 优化后该阶段正常只持续数秒，不引入复杂的伪进度百分比。
- API 未就绪时状态文案应继续表达“等待商务通登录能力”，不能显示虚假绿色。

## 安全边界

- 本地服务仍只绑定 `127.0.0.1:18766`。
- HTTP 令牌仍保存在被 Git 和发布包排除的 `runtime/`。
- 不持久化请求头、公共查询参数、Token 或日志正文。
- 历史接口 URL 必须为 `http` 或 `https`，并保持日志中解析到的精确地址；不猜测、不拼接域名。
- 数据库继续以 `readonly` 和 `fileMustExist` 打开。
- 不输出访客个人信息、聊天正文或认证材料。

## 测试策略

### 日志解析

- 历史接口 URL 与当天认证材料组合后可形成可用快照。
- 历史公共查询参数和请求头不得被复用。
- 当天新接口 URL 覆盖历史 URL。
- 缺少当天查询参数或请求头时身份保持未就绪。

### 并发服务

- 多条会话实际并发执行，最大并发数不超过 4。
- 每条会话仍保持 `visitor_info -> visitor_card` 顺序。
- 任一会话失败时整批失败且不缓存部分结果。
- 输出顺序稳定，统计结果与串行实现一致。
- 现有 single-flight、自动来源隔离和项目白名单测试继续通过。

### 回归与实机验证

- 运行商务通相关测试与基础测试。
- 运行完整测试集。
- 只读计时验证 13 条会话耗时达到目标区间。
- 重启打包版 GUI，确认本地 API 在具有当天认证材料时数秒内就绪。
- 不运行真实 `run-daily`，不写目标 Excel。

## 验收标准

- 当天认证材料已存在且历史接口 URL 可用时，本地 API 在 5 秒级别内就绪。
- 13 条会话、26 次服务端读取在正常网络下约 2～5 秒完成。
- 任一会话异常时不产生部分成功数据。
- 自动来源记录数、账户归属和小时报/日报指标与优化前完全一致。
- GUI 主线程不执行商务通数据库或网络读取。
- 日志、报告和发布包不新增任何认证材料。

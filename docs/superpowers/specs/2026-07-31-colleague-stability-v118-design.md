# 2026.7.31.118 同事端稳定性修复设计

## 背景与证据

117 版在同事电脑上仍出现三类关联问题：

1. 百度步骤偶发长时间无输出，窗口看似卡死，停止按钮也像失效。
2. 快商通服务显示已启动，但当前项目仍无法取数；不同电脑分别出现身份无法映射、数据库结构不兼容。
3. 重新扫描按钮偶发不可点，路径错误时还可能弹出隐藏在主窗口后的目录选择框。

2026-07-31 沈阳白的真实运行报告进一步确认：

- 第一百度来源 API 成功返回 3 个账户。
- 第二百度来源连续两次未通过完整性校验。
- 按多来源原子规则，程序丢弃第一路临时结果并将整个项目降级到浏览器；浏览器两路均成功。
- 当前 `baidu_api_attempt_report.json` 只保存项目级错误类别，丢弃了具体来源和安全错误详情，因此无法从发布后的日志定位第二路究竟是日期、账户、汇总还是响应结构异常。
- 本次快商通步骤发生时本地服务尚未启动，任务按配置将快商通指标置 0；服务稍后才随 GUI 模式切换启动。

代码检查还确认了以下缺陷：

- Electron 数据目录虽能保存到机器设置，但扫描器没有真正使用该目录。
- 健康检查只要求“至少一个项目已绑定”，所以服务可显示绿色，但当前项目仍可能未绑定。
- HTTP 服务、客户端和置 0 报告连续吞掉了真实的安全错误类别。
- 任一数据库读取失败会让该身份已经读到的推广 ID 一并丢失。
- 自动探测时，未被实际选用的旧版数据库错误可能遮蔽新版身份映射错误。
- 路径错误会从状态回调中同步打开原生目录选择框；若窗口落到无边框主窗后面，整个界面会表现为无响应。
- 人工导出模式会禁用重新扫描按钮。

## 目标

版本目标为 `2026.7.31.118`：

- 让新版和旧版快商通路径选择都真正生效。
- 让“API 已启动”与“当前项目可取数”成为两个明确状态。
- 保留严格的项目身份隔离，同时为新版数据库解析失败提供安全、可验证的只读日志回退。
- 保留快商通不可用时指标按 0 继续的业务规则，但把可行动的安全原因写入日志和报告。
- 让路径选择和重新扫描不再阻塞 GUI。
- 让百度多来源 API 失败能定位到具体来源及安全完整性原因。
- 百度阶段长时间无输出时主动提示，并始终保留可用的停止入口。

## 非目标

- 不改变 PyInstaller onefile 的父子进程模型；正常启动出现两个同名进程不视为重复任务。
- 不操作快商通客户端界面，不使用 OCR，不读取桌面控件。
- 不人工绑定身份，不允许一个身份模糊匹配多个项目。
- 不改变百度 API 20 秒自修复预算和多来源全成全败规则。
- 不运行真实 Excel 写入作为测试，不改动 Excel 结构或业务口径。

## 设计

### 1. 路径选择与扫描

- 机器设置继续保存 `data_root` 和 `install_root`，只用于当前电脑，不进入发布包。
- Electron `data_root` 同时接受直接选择 `OnlineWebCSNew`，或选择包含 `OnlineWebCSNew` 的父目录。
- 明确选择 Electron 数据目录时只诊断 Electron；明确选择旧版安装目录时只诊断旧版。
- 自动扫描时可以同时尝试两类后端，但未被采用的后端错误不得覆盖已识别后端的主要错误。
- 状态回调不再自动打开目录选择框，只更新状态和日志。
- “选择数据目录”“选择旧版安装目录”“重新扫描”保持显式按钮。
- 重新扫描按钮在人工导出模式也保持可用；点击后先持久化切换为本地 API 模式，保存成功后启动服务并扫描一次，保存失败则不扫描。

### 2. 身份识别与数据库兼容

- 每个 Electron 身份逐库读取时隔离故障：一份数据库失败不再丢弃同身份其他已成功数据库的结果。
- 数据库 ID 与日志 ID 取并集，再进行项目映射。
- 日志回退只读取当前日期、结构化的 `visitorCustomField` 记录，只匹配项目配置中正式声明的 `kst_ids`。
- 只有全部证据唯一指向一个项目时才绑定；无匹配、多项目冲突或身份指纹变化时继续拒绝绑定。
- 旧版数据库继续走旧版只读适配，不使用 Electron 日志回退。
- 诊断报告只记录身份哈希、数据库计数、命中项目和安全错误类别，不记录原始推广 ID、对话内容或真实路径。

### 3. 服务状态与当前项目状态

- `/health` 保留全局服务状态，同时返回安全的 `bound_project_ids` 和 `unbound_project_ids`。
- GUI 将状态拆成：服务未启动、服务已启动且当前项目可用、服务已启动但当前项目未映射、数据库不兼容或路径不可用。
- 项目切换后立即根据当前项目重新计算显示状态，不再用“任意项目绑定成功”代表当前项目可用。
- 请求未绑定项目时，服务返回稳定的安全错误类别；客户端保留类别，不暴露身份或数据库细节。

### 4. 快商通失败报告

- 回环请求失败、项目未映射、数据库不兼容、客户端未运行、路径不可用分别归类。
- `allow_zero_on_unavailable` 仍然生效，百度流程继续；但 `kst_parse_report.json` 的 `warnings` 和安全诊断字段记录真实类别。
- GUI 日志显示可行动文案，例如“API 已启动，但沈阳白尚未映射；请登录对应快商通后重新扫描”。
- 相同错误做节流，避免重试刷屏；状态变化时立即输出一次。

### 5. 百度多来源诊断与无输出提醒

- 每次 API 尝试报告增加 `source_id`、`source_name`、`api_profile` 和经过白名单处理的 `safe_detail`。
- 安全详情仅允许日期不一致、未知推广 ID、汇总不一致、字段非法、响应结构异常等受控类别；不得写 Token、Secret、请求头或原始响应。
- 多来源失败时保存已完成来源的安全状态以及失败来源，仍不提交任何部分 API 数据到标准报告。
- GUI 跟踪任务开始时间、最近一条输出时间和当前步骤。百度步骤连续 45 秒无输出时显示一次“百度步骤长时间无输出，可点击停止”，不自动杀进程、不修改生产重试预算。
- 停止操作保持异步，终止当前任务子进程后恢复按钮状态；同一任务不允许重复启动。

## 测试与验收

- Electron 自定义路径的父目录和直接目录均可发现。
- 明确后端路径不会被另一后端错误遮蔽。
- 单库损坏时仍保留其他数据库和严格日志证据。
- 日志证据冲突时拒绝绑定。
- 服务对任意项目可用但当前项目未绑定时，GUI 不显示“当前项目正常”。
- 人工导出模式点击重新扫描会安全切换到本地 API 并只扫描一次。
- 路径错误不弹隐藏模态窗口，停止和扫描按钮可操作。
- 快商通置 0 报告保留安全失败类别且不泄漏原始 ID、对话或路径。
- 百度第二来源完整性失败时报告明确指出来源和安全原因，同时验证第一来源临时结果未被提交。
- 百度步骤 45 秒无输出只提醒一次，收到新输出后计时重置。
- 运行相关单元测试、基础测试、打包审计和启动冒烟；不执行真实 `run` / `run-daily`。

# 全项目快商通本地 API 模式设计

## 目标

将快商通数据获取升级为全局配置：默认优先使用本地 API，人工导出仅作为用户主动选择的应急模式。每台电脑只运行一个随 GUI 生命周期托管的本地 API 服务，该服务自动发现本机商务通安装目录，并为同一客户端中的多个项目身份完成路由。

本设计只定义方案，不执行代码或配置变更。

## 稳定性边界

昆明牛当前已完成自动来源与人工完整导出的实数对账，可评为 8.5/10：

- 双方均为 26 条记录。
- 账户分布均为 14/1/11。
- 未匹配记录均为 0。
- 三个账户的五项指标逐项一致。
- 打包版 GUI 已验证能自动启动本地 API。

其他项目在完成同等级对账前不视为已验证。全项目完成身份识别、版本兼容和逐项目对账后，目标稳定性为 9/10。登录状态、商务通服务端接口和客户端版本变化仍属于外部依赖，不承诺无条件 100% 可用。

## 全局模式

快商通数据源由应用级配置统一控制，不再由昆明牛项目单独控制。

全局状态只有两种，且互斥：

- `local_api`：API 自动获取。
- `export`：人工导出对话。

默认值为 `local_api`。用户切换后对本机所有项目的后续任务生效，不改变已经运行中的任务。

建议的应用配置语义：

```json
{
  "kst_data_source": "local_api",
  "kst_allow_zero_on_unavailable": true
}
```

项目配置继续保留每个项目自己的导出目录、账户名称、推广 ID 和其他业务映射。安装目录、身份绑定和探测结果属于本机状态，不写入公共项目配置。

## GUI 设计

### 系统菜单

删除实时日志区域 KST 控件的来源切换能力，在现有“系统”菜单中新增子菜单：

```text
系统
└─ 快商通模式
   ├─ API 自动获取
   └─ 人工导出对话
```

该子菜单必须复用现有系统菜单组件和样式，包括：

- 字体、字号和字重。
- 菜单宽度、内边距和行高。
- 圆角、阴影和边框。
- 悬停、按下和选中颜色。
- 与现有单选项一致的选中标识。

不得再次使用 Windows 原生白色 `QMenu` 样式，也不得复制一套独立样式常量。系统菜单样式组件是唯一视觉来源。

### 实时日志状态

实时日志右上角只显示：

```text
● KST  ● 实时
```

KST 状态不可点击，鼠标指针保持普通状态：

- 绿色：回环 API 正在监听，健康检查为 `ok`，必需接口可用。
- 灰色：API 未监听、商务通未登录、安装目录不可用、身份或必需接口未就绪。

悬停提示可以显示经过脱敏的诊断信息：

- 回环端口。
- 商务通客户端版本。
- 已发现的身份数量。
- 当前故障类别。

提示中不得包含聊天正文、认证令牌、手机号、微信号或访客身份信息。

## 本地 API 架构

### 单服务模型

每台电脑只监听一个固定回环服务：

```text
http://127.0.0.1:18766
```

服务随 GUI 启动、托盘驻留和真正退出：

- 已有兼容服务时复用，不重复启动。
- GUI 自己创建的服务在 GUI 真正退出时停止。
- 外部服务失联后自动检查并尝试接管。
- 隐藏到托盘不停止服务。

### 多身份注册表

本地服务维护一个身份注册表，负责：

1. 自动发现本机商务通安装根目录。
2. 扫描本机日志和数据库中的全部可用身份。
3. 对每个身份执行只读能力检查。
4. 将项目映射到唯一身份。
5. 缓存经过验证的本机绑定。

身份映射顺序：

1. 优先使用本机已有且仍有效的项目绑定。
2. 使用项目账户配置中的快商通推广 ID，与候选身份数据库中的推广 ID 求匹配分数。
3. 只有最高分唯一且达到最低可信条件时自动绑定。
4. 无唯一结果时保持未绑定，不猜测身份。

同一身份可以服务一个或多个项目，但最终返回结果必须按项目配置的推广 ID 白名单过滤。

本机绑定建议保存到用户本地应用数据目录，不进入安装包、公共仓库或授权配置包。软件升级不能覆盖该文件。

### 请求路由

小时报接口保持统一：

```text
GET /v1/kst/hourly?project_id=<项目ID>&date=<日期>&period=<时段>
```

请求处理流程：

1. 根据 `project_id` 加载项目的账户和推广 ID 白名单。
2. 从身份注册表取得该项目的本机身份。
3. 使用该身份当天的自动推送来源凭证查询服务器。
4. 用只读本地数据库补充推广 ID 和必要归属信息。
5. 只返回白名单项目的聚合指标。
6. 完整校验账户数量、账户名称和五项指标后才标记成功。

不得把用户点击历史查询后产生的本地缓存当作服务器自动推送来源。

## 安装目录与版本兼容

自动发现采用能力探测，不只依赖版本号：

- 检查常见安装目录及环境变量。
- 检查 Electron 主程序。
- 检查 `package.json` 和客户端版本。
- 检查日志目录、身份目录和 `VISITOR*.db`。
- 检查 SQLCipher 只读桥和必要字段。
- 检查当前日志是否具有必需服务端接口。

自动发现失败时，在系统菜单的快商通相关设置中提供：

- 选择商务通根目录。
- 重新扫描安装目录。
- 重新扫描身份与项目绑定。

路径选择和身份绑定均为本机设置，不写入公共项目 JSON。

不同版本应通过独立的发现适配器或数据库结构适配器兼容。遇到未知结构时明确标记不兼容，不输出伪成功数据。

## 数据源与失败处理

### API 自动获取模式

每个项目独立执行 API 查询：

- 查询成功：使用 API 数据。
- API 服务不可用：该项目快商通五项指标按 0，百度数据继续。
- 身份未绑定：该项目快商通五项指标按 0，百度数据继续。
- 响应账户或指标不完整：视为 API 不可用，按 0 继续。
- 多项目任务中的一个项目失败，不阻断其他项目。

API 模式不得自动读取人工导出目录，避免旧文件或历史查询数据被误认为实时自动来源。日志必须明确显示降级原因，但不输出敏感异常内容。

### 人工导出模式

用户在系统菜单主动选择“人工导出对话”后，所有项目恢复现有导出文件流程：

- 使用各项目独立的导出目录。
- 只接受规定时间范围内的最新文件。
- 不与 API 数据混合。
- 不在任务运行中自动切换回 API。

用户重新选择“API 自动获取”后，后续任务恢复全局 API 模式。

## 状态语义

KST 灯只表达本机 API 服务健康状态，不表达某个项目本次数据一定成功：

- API 进程与必需基础能力正常：绿色。
- API 未监听或基础能力异常：灰色。

项目身份未绑定、项目查询失败等项目级问题显示在实时日志和任务结果中。这样可避免因为一个项目未绑定而把整个本地服务误标为停止。

## 安全约束

- API 只允许监听 `127.0.0.1:18766`。
- 数据库连接强制只读和文件必须存在。
- 不修改商务通安装目录、数据库或进程内存。
- 认证材料仅从当前登录日志载入内存。
- 不持久化认证令牌。
- 默认 API 只输出小时报需要的聚合指标。
- 健康检查和日志不输出访客隐私或聊天正文。
- 自动身份绑定只有在唯一可信匹配时成立。

## 验收方案

### 单项目对账

每个正式项目分别选择一个完整日期，比较 API 自动来源与人工完整导出：

- 原始记录总数一致。
- 账户归属数量一致。
- 未匹配记录均为 0。
- 五项快商通指标逐账户一致。
- 不写正式 Excel 即可完成前置对账。

只有全部条件通过的项目才能标记为“API 已验证”。

### 多身份与多机器

至少覆盖：

- 同一台电脑、同一客户端、多个身份。
- 同一身份服务多个项目。
- 两台不同电脑登录不同身份组合。
- 身份新增、移除和重新登录。
- 商务通未启动和未登录。
- API 运行中外部服务退出。
- 人工模式与 API 模式的全局切换。

### 打包版

正式 EXE 必须验证：

- KST API 管理器和状态控件已打包。
- SQLCipher 只读数据库桥资源已打包。
- EXE 启动后 18766 健康检查通过。
- 系统菜单样式与其他系统子菜单一致。
- KST 状态不可点击且灰绿状态正确。
- GUI 真正退出后，由 GUI 创建的端口被释放。

## 上线顺序

1. 实现全局菜单和配置，但先保持现有项目行为。
2. 实现多身份注册表和项目路由。
3. 按项目逐一完成只读对账。
4. 在至少两台同事电脑完成打包版验证。
5. 所有正式项目通过后，将全局默认模式设为 API。
6. 保留人工导出全局开关作为长期应急能力。
